Secrets your agents can use. Values they never see.

edgePass is a local OpenBao console for Windows. It hands a secret to a child process through its environment — never through a chat message, a log line or a command line. You do not need to know Vault: install OpenBao, initialize it, paste a token.

OpenBao 2.x on 127.0.0.1:8200 is required. The installer is per-user and needs no administrator rights.

The problem

The leak happens before the code

When an agent writes the code and runs the commands, a credential has three easy ways out — and all three look harmless at the moment they happen.

A key in a .env file

Committed by accident, then copied into every container and every backup.

A token pasted into a chat

It stays in the transcript, in the model's context and in whatever logs the harness keeps.

A secret in a command line

Visible in shell history, in the process list and in any screenshot taken for a bug report.

What it does

A console, not a server

edgePass administers a vault that runs on the same machine. It does not serve secrets to your containers — OpenBao does that — and it never keeps its own copy.

Lists, searches and copies secrets

From a local OpenBao, on both KV v1 and KV v2 mounts. The mount version is detected, so the paths are the right ones.

Injects into a child process by environment

A secret reaches the process that needs it through its environment, never as an argument. It is not persisted anywhere.

Opens the vault when needed, seals it on demand

The widget watches the seal state and can seal the vault after a period of inactivity.

Finds secrets by name, with tokens

Complementary tokens, all of them: infisi cb2 means Infisical plus the path cb2.

Speaks a named-pipe contract

Any local agent can ask for a secret without receiving the value: it asks the widget to place it in the child's environment.

Watches the local CI runner

When the self-hosted GitHub Actions runner stops, the widget says so and can repair it.

Limits

What it does not do

Said plainly, because this software holds credentials and the boundary is the point.

It does not replace OpenBao

OpenBao is a prerequisite, not an optional dependency. Without a vault, edgePass has nothing to talk to.

It does not run a public endpoint

Every request must go to loopback. It does not serve secrets to containers and does not keep a copy of the vault.

It does not print, log or write values

Not to the pipe, not to disk. The metadata index is kept; the values are not.

It is not audited

Version 0.5.1, early, interfaces can change between minor versions. Read DISCLAIMER.md first.

Quick start

Four steps to the first secret

Windows only for now. macOS and Linux are ports, not build flags — see the repository for what is missing.

  1. Install and start OpenBao

    Local, listening on 127.0.0.1:8200. The prerequisites page covers install, service and seal.

  2. Initialize and unseal it

    Keep the init file off every repository and out of every cloud sync folder.

  3. Run the edgePass installer

    Per-user, no administrator rights. The pill docks to a screen edge.

  4. Set the address and load the token

    Config → Vault. The token goes to the Windows keychain, not to a config file.

Give the skill to your agent. The installer ships the app, not the agent instructions. Run powershell -File scripts\install-skills.ps1, then ask in your own language: “use edgepass”. The agent asks the widget to inject the value; it never sees it.

On the name. edgePass is also a mobile puzzle, a bridge pass, an optical filter and a course. This project is none of those: it is a local OpenBao console for Windows. The name is used descriptively, with no affiliation.

This software manages credentials. A mistake can expose or destroy them.
